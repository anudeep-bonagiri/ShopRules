# Decisions

Each entry: the decision, why, the consequence.

**D-1. Polaris React for the admin.** The product is for people who live in Shopify admin; Polaris is Shopify's own component library and the owner's token sheet (`docs/design/DESIGN.md`) is Polaris-derived. Consequence: the React package is deprecated upstream in favour of web components; it still builds and renders. We extend it with `stitch.tsx` for the feed cards and the inspector.

**D-2. Vercel Blob as the store, one versioned document per workspace.** The team's Supabase and InsForge credentials were not available from this environment on the night; Blob needed no extra account and ships with the deploy. Consequence: no SQL, no multi-user auth. Overwriting one file with ETag preconditions lost writes because reads lagged, so every write is a new immutable version and the newest is found through the listing API (`db.ts`). The Postgres schema is kept in `apps/web/supabase/migration.sql` for self-hosting.

**D-3. Thinking off for Nemotron structured calls.** Nano returned empty content on a long classification prompt because reasoning consumed the completion budget. `chat_template_kwargs.enable_thinking=false` fixed it and cut latency. Consequence: the prompts carry the reasoning structure; `NEMOTRON_ULTRA_THINKING=1` is there for the decision step.

**D-4. Strict official domains for tariff and safety rules.** In prefer mode the origin-tariff rule surfaced a toy-retailer blog and a filament shop. Strict mode on cbp.gov, ustr.gov, federalregister.gov, trade.gov, hts.usitc.gov, whitehouse.gov, cpsc.gov, fda.gov, ftc.gov, oehha.ca.gov keeps the evidence official. Consequence: some rules return no results on some days; that is reported as "nothing new", not padded.

**D-5. The verifier checks presence only.** A quote must appear in the extracted text (normalized substring, then 6-word shingles at 80%). It does not judge meaning. Consequence: rejected claims are shown, not hidden, and alerts carry "might apply" when the model is unsure.

**D-6. One workspace write per check run.** Rules run three at a time and their bookkeeping, new alerts, and the product's last-checked stamp land in one write (`applyCheckBatch`). Consequence: fewer conflicts, and a check that fails midway loses nothing.

**D-7. Rule Forge runs on Token Factory Sandboxes with networking off.** The generated code reads the Tavily text we already fetched; it never fetches. Consequence: deterministic, cheap, and a passing check can be re-run without a model. Without `NEBIUS_PROJECT_ID` the forge is labelled "Not run".

**D-8. Daily cron on the public deployment.** The Hobby plan allows one run a day; the code is written for six hours. Consequence: judges run checks by hand from the product page, which is the demo path anyway.

**D-9. The extension sends page fields with the URL.** Marketplaces block readers; the extension already has the DOM. Consequence: watching from the page works even when Tavily Extract gets nothing, and the demo seed uses the same path.

**D-10. No em dashes in prose, including model output shown to sellers.** `plain()` in `pipeline.ts` replaces them in headlines, claims, and steps. Consequence: one less thing that reads as machine-written.

**D-11. Deterministic pricing; the model reports facts only.** The live demo once cut a lamp's price after a duty increase because Ultra applied a 35% target margin to the new cost on a product earning 55%. Now `apps/web/src/lib/pricing.ts` owns the math: duty applies to the dutiable share of landed cost (default 85%, not freight), the strategy keeps the seller's current margin unless it is already under target, tiny moves are absorbed, and a positive cost change can never yield a lower price (asserted in `pricing.test.ts`). The Ultra prompt no longer mentions prices; `suggested_price` from the model is discarded and the `PricingResult` is stored on the alert and rendered by the web app and the extension from the same bundled file. Consequence: every dollar on screen is reproducible from inputs the seller can see and edit.

**D-12. HTS from a curated catalog, not free text.** Nano classified a desk lamp as 8531 (signalling apparatus) at 92% confidence. `hts-catalog.ts` holds about 100 four-digit headings common in Etsy, Shopify, and Amazon catalogs; the classifier picks from them as an enum, a keyword matcher provides the fallback and a sanity check, and an off-list or unsupported heading is capped at 0.5 confidence with the catalog match beside it. The 6 or 8 digit refinement stays a free-text suggestion labelled "verify with a broker". Consequence: tariff rules search the right heading, and a wrong model guess is visible as "guarded", never silent.

**D-13. Price points come from three named sources.** The listing when it is added, the extension when the seller visits the page (debounced to once an hour per product), and the daily refresh that reads the page again without a model (Shopify stores answer their public `.json` endpoint; other pages go through Tavily Extract and `price-parse.ts`). A reprice marked done also writes a point. Consequence: the price chart has history, price-change alerts are possible, and the product page says exactly where each point came from.

**D-14. Compare-and-swap workspace writes.** Workspace versions are now create-only blobs named by version number (`v000000000042.json`); two writers that both read version 41 cannot both create version 42, so the loser re-reads and reapplies, up to five times with jitter. Conflicts are counted on the run record. Consequence: a cron run, a user check, and a cost-receipt write can no longer overwrite each other silently; the Postgres move stays optional.

**D-15. Deterministic guardrails on every model verdict, and an eval that measures them.** The seller wanted the NVIDIA models to spot changes without wandering: `sanity.ts` audits each Ultra verdict after the quote verifier. A duty number must be stated by a backed quote or be the difference of two stated rates (a quote that moves a rate "from 7.5 to 25 percent" is a 17.5 point change even if the model wrote 25); duty math is dropped from safety, tax, and policy rules; dates before 2018 or more than 18 months out are dropped; the action type must fit the rule family; quotes are read in their source passage and must name this product, its heading, or its origin, while a passage that names other headings or other countries only is rejected and exclusion sentences ("does not change requirements for toys") do not count; a finding already raised for the rule in the last 45 days is dropped; severity follows the numbers. The prompt also receives the rule's alert history and the price trend so the model reports only what is new. `scripts/eval.mts` replays golden cases (`apps/web/src/lib/fixtures/eval-cases.json`, including traps) through the production prompt, the verifier, and the guardrails and writes `docs/EVAL.md`; `--offline` replays recorded verdicts without a model call. Consequence: nothing here invents facts; it only removes, softens, or corrects, and every adjustment is listed on the alert's evidence page.

**D-16. A bot wall is not a listing.** Etsy and Amazon answer some fetches with a challenge page whose title is the bare hostname. `looksBlocked()` in `pipeline.ts` drops that text, `indexedListing()` asks Tavily Search for the listing URL restricted to the store and keeps only the result with the same listing id, ASIN, or product handle, and `cleanTitle()` refuses a hostname or a store name as a product title. On Etsy and Amazon the page title is the listing title, so it outranks the classifier's name; on a Shopify store it carries the shop name, so the classifier wins. A store homepage is refused with the listing path shapes in the message. Consequence: no product is ever called "www.etsy.com", and a blocked fetch still yields the listing from Tavily's index.

**D-17. Postgres is the store; Blob is the alternative backend.** At 03:25Z on 2026-10-30 the Vercel Blob store was suspended ("Your store is blocked"; creating another store failed with "usage threshold limit is reached") after a day of testing. Every read of a workspace listed its versions, Vercel bills a list as an advanced operation, and the Hobby plan has a small monthly allowance. The store moved to one Postgres row per workspace (a free Supabase project in us-east-1, the same `Workspace` document, an optimistic version check in the upsert) behind one `DocStore` interface in `db.ts`. Consequence: one query per read, no listing, no read lag; the Blob backend stays behind `BLOB_READ_WRITE_TOKEN` with the caveat written beside it in the README. Workspaces created on Blob before the suspension could not be migrated because reads were blocked, so the public demo starts fresh.

**D-18. The verifier is scored, not described.** `seed/generate.mts` writes a deterministic fixture (synthetic pages on `.invalid`, planted misquotes by class, decoys that look wrong but are legitimate) with a hidden answer key that only `scripts/facts.mts` reads. Two rules came out of the first scoring: a fuzzy (shingle) match must carry every number of the quote verbatim, because a changed figure inside a long quote passed; and an elided quote ("...") is checked part by part on one page. Consequence: the Devpost page quotes how many planted misquotes were rejected and how many decoys accepted, and the ones that go the wrong way are named in `docs/RESULTS.md` and `docs/not-built.md`.
