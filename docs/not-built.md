# Not built

Not built is a complete answer. This is what Shop Rules does not do at submission time, so a judge does not have to guess.

- **No store API integration.** Shop Rules never talks to the Shopify, Etsy, or Amazon seller APIs. Listing data comes from the page (the Shopify public products JSON endpoint, JSON-LD, Open Graph, or the fields the extension scrapes; Tavily Extract for URLs pasted into the web app). "Draft reprice" copies the new price to your clipboard and marks the alert done; it does not change the listing. Shopify write-back through OAuth was planned and not started.
- **No order API.** Sales for the nexus bars come from a Shopify or Etsy orders CSV the seller uploads in Settings (aggregated per state and year, rows discarded) or from figures typed by hand. Nothing is pulled from a store.
- **No tariff classification authority.** The heading comes from a curated catalog of about 100 four-digit headings; the classifier picks from it and a keyword check guards it. The general duty rate is read from hts.usitc.gov with Tavily Extract when the schedule page parses, and is labelled "not read yet" when it does not. None of this is a ruling; the product page says "verify with a broker".
- **Nexus thresholds start as seeds.** The 46 jurisdictions ship as seed values dated in the file. A threshold is shown as verified only after Tavily Map and Extract read the state revenue site and a parser found the dollar and transaction tests in the page text with the quote. Until then the Watchlist says "seed value, last verified never".
- **No login.** A workspace is a cookie plus a token. "Open on another device" carries the token in a link, and the token can be rotated. There is no password, no email, no sharing between people. Anyone with the token can read the workspace.
- **Telegram delivery needs a bot token on the server.** The public demo deployment does not have one set, so alerts there appear in the app, the extension badge, and Chrome notifications only. Email digests were not built.
- **Rule Forge runs its sandbox only when `NEBIUS_PROJECT_ID` is set.** Without it the agent still writes the check and the tests, and the forge is labelled "Not run". Forged checks are not yet used to skip the model in the daily run.
- **The scheduled run is once a day** on the public deployment (Vercel Hobby). It refreshes prices first (no model), verifies up to three stale nexus states per workspace, then runs due rules with a 240 second budget. There is no cursor to resume where it stopped; the next day starts from the top.
- **The Chrome extension is not in the Chrome Web Store.** It is loaded unpacked from `extension/dist` or the zip. Its scrapers are tested against fixture pages that mirror Amazon, Etsy, and Shopify markup (including a custom-domain Shopify store with the `.json` endpoint mocked), not against the live sites in an automated run.
- **The verifier checks presence, not meaning.** It confirms a quote exists in the extracted text. The guardrails add coherence checks (the number must be in a backed quote, the quote must be about this product, the action must fit the rule) but nothing judges whether a quote truly supports a claim. Rejected claims and every guardrail adjustment stay visible.
- **Competitor compare is best effort.** It lists prices Tavily Search surfaced in result text, cached for 24 hours per product. When a marketplace page does not expose a price in the snippet, the row has no price.
- **No multi-product bulk import.** One URL at a time, or one page at a time from the extension. Twenty-five products per workspace on the public demo, with daily caps of 40 checks, 10 new listings, and 20 compares.
- **One store at a time.** The public demo runs on Postgres (one JSON document per workspace, optimistic version check) after the Vercel Blob store was suspended under the Hobby usage threshold the night before the deadline (D-17). Blob stays as the alternative backend with compare-and-swap versions; without a Blob token or a database URL in development the app runs on a local file store with canned model answers (demo mode, labelled in the UI). Workspaces from the Blob store were not migrated.
- **The eval is ten golden cases.** `npm run eval` measures the production prompt plus verifier plus guardrails on realistic excerpts with known answers, including traps. It is not a benchmark over live pages, and the offline replay (`npm run eval:offline`) exercises the verifier and guardrails, not the model.
- **The verifier's fuzzy path has known gaps.** On the planted fixture under `seed/` it lets through a negation inserted into a long quote and two non-adjacent sentences of one page joined as if contiguous; the measured counts are in `docs/FACTS.md` and the cases in `docs/RESULTS.md`. Exact matches, changed numbers, fabricated sentences, and quotes from unfetched pages are caught.
